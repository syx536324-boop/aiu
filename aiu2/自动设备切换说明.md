# YOLO 自动选择 GPU / CPU

## 怎么使用

双击桌面的 **YOLO 实时推理应用** 快捷方式，打开 http://127.0.0.1:8765/ ，选择模型和摄像头，点击“启动实时检测”。无需手动选择计算设备。

页面“计算设备”显示当前实际设备；检测设置下方显示选择原因、GPU 利用率与剩余显存。

## 默认切换规则

每 3 秒采样一次 NVIDIA 显卡 0 的状态。GPU 使用率与显存是两项不同指标。

| 情况 | 行为 |
|---|---|
| 启动时显存占用 ≥85%、剩余显存 <1536MiB，或 GPU 利用率 ≥90% | 先使用 CPU |
| 运行中显存占用 ≥85%，或剩余显存 <1536MiB | 下一次采样后切换 CPU |
| 运行中 GPU 利用率持续 ≥90%，达到 15 秒 | 切换 CPU |
| GPU 利用率 ≤60%、剩余显存 ≥3072MiB、显存占用 ≤65%，连续保持 30 秒 | 自动恢复 GPU，且距离上次切换至少 30 秒 |
| CUDA 显存不足或 CUDA 推理失败 | 在 CPU 上重试当前帧，然后等待恢复条件 |
| CUDA 不可用或 NVIDIA 监测不可用 | 保守使用 CPU |

## 通俗解释

千问与 YOLO 共用一张显卡。显卡繁忙时，YOLO 把同一份模型移到 CPU 执行，给显卡腾出空间。恢复后再搬回显卡。不会重新训练，不会修改 best.pt。

切换会短暂停顿；CPU 检测帧率通常更低。现阶段 CPU 继续使用 PyTorch，并未接入单独的 C++ ONNX 实验程序。

## 技术边界

- 采样使用系统 NVIDIA nvidia-smi，无需安装额外依赖；子进程在 Windows 上隐藏窗口，最多等待 2 秒。
- 监测的是整张 GPU 的总负载，包含 YOLO、Ollama、游戏等；无法仅凭该指标确定是哪一个程序导致繁忙。YOLO 自己的高负载也可能触发回退。
- 在帧之间迁移模型，重建 Ultralytics 推理器，并清理不再使用的 CUDA 缓存；CUDA 上下文本身仍可能保留少量显存。
- 采样不是实时资源预留，另一个程序突然大量申请显存时仍可能触发 OOM；程序会捕获 CUDA 相关错误并尝试 CPU 回退。
- 自动切换只作用于摄像头网页，不修改训练命令、图片推理命令或 Ollama 设置。
- 已通过模拟 GPU 压力读数、实际 GPU/CPU 推理的设备切换测试，以及高负载持续时间与恢复策略检查。尚未进行真实 Ollama 并发压力或摄像头连续切换实测。详细结果见 GPU_CPU自动切换测试报告.md。

## 模块与接口

- `yolo_demo/services/device_policy.py`：显卡采样、阈值、持续时间与恢复策略。
- `yolo_demo/services/adaptive_inference.py`：模型迁移、设备状态与 CUDA 故障回退。
- `yolo_demo/services/live_inference.py`：摄像头采集与检测循环。
- `GET /api/status`：新增 `device_mode`、`device_reason`、`gpu` 字段；前端只展示后端判断结果。

启动命令：

```powershell
cd D:\aiu2
.\.venv\Scripts\python.exe -m yolo_demo web
```

阈值集中在 `device_policy.py` 中，可按实际并行运行效果调整。
